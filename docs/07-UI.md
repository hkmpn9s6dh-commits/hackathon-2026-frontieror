# 07-UI — 結果站

本站只做一件事：把「六題 × 十個實例」的可行性、分數、耗時放在一張畫面上，讓人
一眼看出**哪一題是 60 秒的牆**。它不是產品界面，是舉證頁，所以照「網頁儀表板」
樣板（`hackathon-2026-paypal` main `f8f6c4f`，見 AME-1134 樣板登記）那條線做，
並照抄它的已知弱點與改法。

## 1. 風格預設

- 紙感淺底 `#f7f5f0`，正文 `#16150f`，次要 `#6b6659`，分隔線 `#e0dbcf`。
- 一個強調色：硃紅 `#b3271e`，只給「不及格 / 0 分 / 逾時」與標題的落款印。
- 一個對比色：墨綠 `#1f5d4c`，只給「比參考好」。
- 字：正文 16px／1.65，標題 34px，數字用等寬（`ui-monospace`）。不用 web font，
  不聯外（站點要能離線開）。
- 版面：單欄，最大 880px；區塊之間 64px；卡片圓角 6px，1px 邊。

## 2. 尺子（學哪一點）

| 尺子 | 學哪一點 |
|---|---|
| `hackathon-2026-paypal` `f8f6c4f` 主屏 | 一張表就是主屏：欄位少、數字右對齊、每欄有單位 |
| `hackathon-2026-jieshan` 線上頁 | 判據可視化：把「判定用的是哪根線」畫出來（這裡是 60 s 的時間軸） |
| `hackathon-2026-osc` 報告頁 | 結論先行：第一屏就給「幾個過、幾個不過、卡在哪」 |
| Our World in Data 的表格頁 | 表格密度與 zebra 不刺眼 |
| Distill 的文章頁 | 圖前一句話、圖後一句話，不堆圖 |

## 3. 一個記憶點

**「60 秒是一堵牆，有一題撞上去了。」**

第一屏右側放一條 60 秒比例尺：橫軸 0–60 s，六題各一根橫條，條的長度是實際牆鐘，
末端標分數。五根短、一根頂到頭（hoffman1993）。300px 縮圖下仍要讀得出「一根頂到邊」，
所以條高 ≥ 12px、間距 ≥ 8px、只在條末放一個數字。

## 4. 主屏規格

- 1280×720 內完整看到：標題、一句結論、六題分數表（≥5 行）、60 秒比例尺。
- 表格六欄：題目／實例／可行性／分數／耗時／備註。分數欄固定 3 位小數。
- 失敗的列整列淡紅底 + 左側 3px 紅條（不是只把字變紅）。
- 每張卡片／表格下方留 ≥16px，不放捲動容器。

六個沒見過的運籌題，同一條生產線：讀 schema、選構造、自己判可行、自己決定什麼時候停。判分用官方檢查器。

2 vCPU / 4 GB / 無網路 / 每題 60 秒 · 參考值＝frontieror/FrontierOR（CC BY 4.0）的 Gurobi 解

橫條＝那一題的平均分，虛線是 1.0（與參考相同）。右列是最慢一次的牆鐘，打 * 的表示撞到我們自設的 55 秒軟停止（留 5 秒寫答案）。紅條＝這一題有實例沒解出來。

0.841估算 六題平均分（參考＝1.000）；34/36 個實例拿到可行解

36 個實例裡 34 個拿到可行解；集合劃分有 2 個實例在 60 秒內找不到覆蓋。 最慢的一次 55 秒上下就停手寫答案（預算 60 秒， 我們自留 5 秒）。

分數照官方評分頁算：最小化題是「參考 ÷ 我們」，最大化題（本場的定向越野）反過來；與參考相同得 1.000，比參考好最多到 2.000。這裡的參考值是基準資料集裡的 Gurobi 目標，不是比賽後台凍結的參考值，所以它是估計，不是成績。

六條生產線

Dial-a-Ride cordeau2006

全部可行

把 36 位乘客的接送塞進 4 輛車：時間窗、共乘容量、最長乘車時間、最長趟次。

怎麼做：最便宜可行插入。每插一對（上車、下車）就從車場重排一次時刻表，用真時刻表判可行性，不用估算。

為什麼：時間窗讓「先排誰」比「走多短」更關鍵，所以要真的排一遍時鐘。

平均分
0.964
最慢一次
42.8s

Orienteering fischetti1998

全部可行

單車、有時間預算，選一條回程閉環，把沿路城市的獎金拿得最多。

怎麼做：按「獎金 / 多繞的路」比值插入城市；插不進去就 2-opt 把路壓短再插。多輪重啟，每輪給獎金加不同噪聲。

為什麼：500 座城，窮舉不可能；但「繞一點多拿很多」的貪心加壓路，能在 60 秒裡逼近參考解。

平均分
0.865
最慢一次
55.2s

OD 整數多商品流 barnhart2000

全部可行

585 個商品各走一條不可拆的路，或退回人工弧（等於賠掉那筆收入）；弧有容量。

怎麼做：最寬路徑貪心：每個商品挑「瓶頸容量最大」的路，而不是最短路——物理弧成本都是 0，最短路只會把貨堆在同一幾條弧上。

為什麼：目標是「別賠錢」，所以排序用收入而不是流量；多種排序各跑一遍取最好。

平均分
0.940
最慢一次
9.8s

機組排班集合劃分 hoffman1993

4/6 可行

100 段航班，15,000 個候選機組輪轉，每一段剛好被一個輪轉覆蓋，成本最小。

怎麼做：三段：min-conflicts 找覆蓋 → 大鄰域（挑幾根已選輪轉，把那幾段航班重解一次）→ CP-SAT 帶提示再優化。

為什麼：成本與長度無關（1–200 對 1–51 段），最優解是「很多很短」，而分支定界是從「很少很長」往下走——這就是它撞牆的原因。

平均分
0.420
最慢一次
55.1s

隨機容量選址 bodur2017

全部可行

先決定開哪些倉（開倉費），再看 1,500 個需求情境各自怎麼送；總容量要撐得住最壞情境。

怎麼做：開倉集合用「從全開往下刪」：每次刪一個最貴的，用抽樣情境估期望成本，容量撐得住且成本下降就刪。送貨用「最便宜配對先送」的貪心運輸。

為什麼：每個情境都解一次 LP 放不進 60 秒；成本係數不隨情境變，所以配對順序只排一次。

平均分
0.915
最慢一次
15.8s

可分割收送的 VRP nagy2015

全部可行

199 位顧客，送貨與取貨可以分兩趟做，但車上任何時刻的貨不能超過容量。

怎麼做：把「送貨」與「取貨」當兩個獨立任務，Clarke-Wright 節約法在兩個容量預算下分組；每組先送後取、區塊內 2-opt，再用帶載重檢查的全序列 2-opt 收尾。

為什麼：同一顧客的送與取可以拆開，這正是題目給的自由；把顧客綁在一起，set-3 上會多走 20%。

0.942

3.7s

撞牆的那一題

集合劃分（hoffman1993）是唯一沒有全部拿下來的題。原因不是「不夠快」， 而是成本與長度無關：15,000 個候選輪轉的成本在 1–200 之間，覆蓋的航班段數在 1–51 之間， 所以最優解是「很多很短的輪轉」。分支定界從第一個可行解（約 33 根長輪轉）往下走， 每一步都要拆掉一根長的換幾根短的，60 秒內走不到。

最密的兩個實例（平均覆蓋 21.6 段、需要約 5 根輪轉）連可行覆蓋都找不到： 100 段航班要剛好被 5 個集合切開，在 15,000 個候選裡是一個針尖。純可行性模型跑 15 秒也還是 UNKNOWN。這是這條生產線目前真正的邊界，不是調參能解決的。

沒有拿下來的實例：

  • hoffman1993 / large_instance_4：60 秒內沒有找到覆蓋，solver 寫出空清單，檢查器因此判「缺少必要欄位」——是沒解出來，不是輸出格式壞了。
  • hoffman1993 / large_instance_5：60 秒內沒有找到覆蓋，solver 寫出空清單，檢查器因此判「缺少必要欄位」——是沒解出來，不是輸出格式壞了。

怎麼覆核

下面每一行都能在乾淨 clone 上跑。檢查器是官方那一份，目標值另外用一份獨立算式重算， 分數按官方公式算。

git clone https://github.com/hkmpn9s6dh-commits/hackathon-2026-frontieror.git
cd hackathon-2026-frontieror
python -m pip install ortools          # 只有 hoffman1993 需要
python scripts/fetch_data.py          # 取 large 實例，按 sha256 校驗
python harness/verify.py --tier tiny  # 只跑六個 tiny 實例，約 20 秒
python harness/verify.py              # 全部 36 個實例
python harness/build_submission.py    # 打包成 submission.zip（< 4 MB）
